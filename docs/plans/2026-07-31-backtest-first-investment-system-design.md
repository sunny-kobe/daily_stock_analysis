# 回测优先的个人投资决策系统总体设计

## 状态

- 2026-07-31：经用户确认，作为后续迭代的产品主线真源。
- 本设计收敛并替代此前以基础设施和治理术语为中心的实施顺序。
- 旧计划中的数据完整性、未来数据泄漏和结果不可改写等技术发现仍然有效，但不再决定用户看到的产品结构。

## 产品目标

系统只解决三个核心问题：

1. 今天对每个持仓或候选标的应该采取什么动作。
2. 产生该动作的策略，在历史测试和模拟观察中表现如何。
3. 当前策略是否已经达到可以进入下一阶段验证的标准。

系统追求扣除成本后的风险调整决策质量，不把单纯涨跌命中率当作最终目标。所有真实交易、资金分配和策略投入使用都由用户确认。

## 用户可见动作

内部继续区分“已有仓位如何处理”和“新增资金是否投入”，因为一只股票可能值得继续持有，但当前不值得继续加钱。这个区分只用于计算、风险检查和结果评价，不直接暴露给用户。

### 已有持仓

- `加仓`：保留现有仓位，并允许在条件满足时分批增加。
- `持有`：保留现有仓位，当前不增加资金。
- `减仓`：降低现有仓位。
- `清仓`：退出现有仓位。
- `资料不足`：关键数据或证据不足，不能给出可靠动作。

### 尚未持有的标的

- `买入`：允许按已确认的分批和风险约束建仓。
- `观察`：暂不投入资金，等待明确条件出现。
- `跳过`：当前不考虑投入资金。
- `资料不足`：关键数据或证据不足，不能判断。

### 映射原则

- 内部 `hold + add_in_batches` 显示为 `加仓`。
- 内部 `hold + wait|no_add` 显示为 `持有`。
- 内部 `reduce` 显示为 `减仓`。
- 内部 `exit` 显示为 `清仓`。
- 缺少关键证据时，任何可执行动作都降为 `资料不足`。
- `reduce|exit + add_in_batches` 等自相矛盾组合视为无效结果，不做猜测性映射。

每条用户可见建议只展示一个主动作，并附：核心原因、主要风险、改变动作的条件和下次复查时间。内部字段可以在调试数据中保留，但不在普通界面和通知中展示。

## 总体主线

### 1. 固定当前策略

先把当前使用的规则固定为一个不可改写的策略版本。策略版本必须说明：

- 适用市场、产品和持有周期；
- 买入、加仓、持有、减仓、清仓和不判断的条件；
- 成本、成交价格、benchmark 和风险假设；
- 哪些部分能够用历史数据重现；
- 哪些 AI、新闻或人工判断只能通过未来模拟观察验证。

没有版本记录的规则不能进入正式回测，也不能宣称表现改善。

### 2. 历史回测

回测是策略进入模拟和真实验证前的主要关口。每次测试必须：

- 只使用当时已经存在的数据；
- 使用下一根可交易价格作为动作起点，不能偷用尚未出现的同日收盘价；
- 扣除手续费、税费、滑点、汇率和产品特有成本；
- 与继续持有、买入持有和预先指定的合适 benchmark 比较；
- 分开报告 5、20、60 个交易日结果；
- 分开报告 A 股、港股、美股和不同产品类型；
- 覆盖上涨、下跌、震荡和高波动阶段；
- 留出策略开发时未使用的验证区间；
- 使用不同起始日期和合理参数扰动反复测试；
- 记录无法计算的指标及原因，不用估计值补齐。

每个策略版本至少展示：样本数、胜率、扣成本净收益、相对基准收益、最大回撤、平均赚赔比、换手和总成本。还必须展示最差阶段和明确失败场景。

胜率必须按动作定义：买入和加仓评价投入后表现；减仓和清仓评价相对继续持有避免了多少损失；持有评价相对退出或基准是否更好。不同动作不能混成一个总胜率。

测试门槛必须在查看结果前固定。一次策略变化只允许改变一个主要规则，避免无法判断改善来自哪里。

### 3. 模拟观察

历史回测通过后，策略每天使用真实可用数据生成建议，但不投入真实资金。系统保存当时的策略版本、输入、建议和后续结果。

模拟阶段用于验证：

- 历史测试之外的新市场环境是否仍然有效；
- AI 和新闻证据层是否稳定；
- 数据缺口和失败行为是否符合预期；
- 实际建议频率、换手和成本是否可接受。

历史回测优秀但模拟阶段失效的策略，退回修改或停用，不能进入真实验证。

### 4. 小额真实验证

只有历史回测和模拟观察都达到预先设定标准，策略才可以进入有限资金验证。

- 每次动作由用户确认。
- 资金上限和风险预算由用户明确指定。
- 系统不连接券商、不生成订单、不自动执行。
- 实际交易继续记录在现有 DSA 持仓账本中，不建立第二本账。
- 实际成交与建议的差异单独记录，避免把执行误差算成策略能力。

### 5. 正式使用与持续改进

正式使用的策略仍然持续记录表现。同一时间只将当前策略与一个候选版本比较，候选版本一次只改一个主要规则。

候选版本即使测试更好，也不会自动替换当前策略。用户只能选择继续观察、投入使用、退回修改或停用。旧版本和旧测试结果永久保留。

## 策略档案

每个策略版本必须记录：

- 策略名称和版本；
- 相对上一版的唯一主要变化；
- 适用范围和明确不适用范围；
- 完整规则及依赖的数据；
- 历史可回测部分和仅可模拟部分；
- 测试协议、数据版本和代码版本；
- 每次历史测试、模拟观察和小额验证结果；
- 用户作出的状态变更及理由。

用户可见状态统一为：

```text
草稿 -> 回测中 -> 回测不通过
                -> 模拟中 -> 小额验证 -> 使用中 -> 已停用
```

状态不会自动前进。数据或测试失败只会阻止进入下一阶段。

## 最小产品页面

### 今日建议

每个持仓只显示一个明确动作、简短原因、主要风险、动作条件和复查时间。安静持仓保持简洁，只有动作变化或证据不足的项目展开。

### 策略与回测

在现有回测入口中展示：

- 当前使用策略；
- 每个策略版本改了什么；
- 当前验证阶段；
- 核心测试成绩；
- 最差阶段和失败原因；
- 用户可以确认的下一步状态。

旧的“历史分析记录命中率”保留为兼容诊断，但必须明确标注“不能代表完整策略表现”。

### 决策记录

按时间展示当时建议、用户决定、实际动作和成熟后的 5/20/60 日结果。普通用户界面使用简单中文，不展示内部枚举和治理术语。

## 保留的底座

以下能力保留，但只作为幕后可靠性条件：

- DSA 持仓、现金、成本和交易的唯一真源；
- 标的身份、产品类型、价格、FX、benchmark 和风险证据检查；
- 决策时输入冻结，禁止使用未来数据；
- 缺少关键数据时返回资料不足；
- 决策、策略版本和完成后的测试结果不可原地改写；
- 5/20/60 日结果和人工反馈记录。

这些能力的作用是保证回测和复盘可信，不作为独立产品主线继续扩张。

## 当前不做

- 复杂机会发现漏斗；
- 机器学习和自动调权；
- 自动策略切换或自动晋升；
- 券商、订单和自动交易；
- 多 Agent 集群或自动外部工作器；
- 每天对全部持仓进行昂贵的深度 AI 分析；
- 通用实验平台和复杂策略治理看板；
- 不能直接改善决策、回测可信度或人工验证效率的装饰性报表。

机会发现只有在“策略记录 -> 历史回测 -> 模拟观察 -> 小额验证”闭环稳定后才重新评估。

## 下一纵向切片

首个切片只完成：

1. 将双轴内部决策映射成一个用户可见中文动作；
2. 固定当前策略版本和测试协议；
3. 修复现有结果评价中会导致错误结论的问题；
4. 对一个可历史重现的策略版本生成可重复的回测成绩单；
5. 在现有回测页面展示策略变化、阶段、核心成绩和失败场景。

不在该切片中实现模拟自动运行、小额资金管理、机会发现或任何交易能力。

## 完成标准

- 用户对每个持仓只看到一个简单明确动作。
- 同一策略版本、冻结数据和测试协议能够重复得到相同结果。
- 回测不使用未来数据，不混合不同周期和产品结论。
- 每个策略变化都有版本、变化说明、测试结果和当前状态。
- 测试报告同时展示收益、风险、成本、样本和失败场景，不以胜率单独下结论。
- 回测失败或资料不足时明确停止，不进入模拟或真实验证。
- 所有状态变化和真实动作仍需用户确认。
