# 每日全持仓模拟可用版设计

## 结论

本阶段只完成一个用户闭环：在持仓页生成当天全部持仓的简明计划，必要时选择单个持仓做详细分析，保存新的不可改写建议和人工决定，并在 5/20/60 个交易日尚未成熟时明确显示等待。

现有全持仓 baseline 只读取冻结快照中的有效旧建议，不会自动创建当天的新决策事件。因此页面必须区分“参考旧建议”和“本轮新建议已保存”，不能把 baseline 覆盖或测试通过误报为新增策略样本。第一次上线验收会显式分析全部持仓，为后续日常轻量复盘建立第一批前向记录；日常使用仍只深挖用户选择的持仓。

## 方案选择

### 方案一：复用现有 API，在持仓页建立两阶段工作流，采用

页面按顺序执行：准备资料 -> 冻结快照 -> 生成全部持仓 baseline。用户看到全部持仓的简单建议和资料状态，再按需选择详细分析。详细分析必须携带同一 `snapshot_hash` 和 `cutoff`，完成后才能产生新的 DecisionSignal、证据 sidecar 和质量上下文。

优点：不新增数据库表、依赖或后端运行状态；复用已经验证的 API 和异步分析任务；用户下周可以直接从页面操作。缺点：页面刷新后需要重新生成当天计划；首次建立全持仓前向样本仍需显式验收 runner。

### 方案二：只提供 CLI，不采用

共享 runner 可以串联 baseline 和深挖，但用户仍需使用命令行，不能算日常可用的产品界面。

### 方案三：新增 daily simulation 表和总控 API，不采用

后端可持久化整次会话，但会引入新的 Schema、状态机和恢复语义。本阶段没有足够需求证明这些复杂度必要。

## 契约

- Goal：让用户在持仓页完成一次可信的每日全持仓模拟，并保存第一批可等待 5/20/60 日评价的新建议。
- Source of truth：DSA 持仓、现金、交易、标的 registry 和风险政策；冻结研究快照；版本化策略 manifest；不可改写决策证据 sidecar。
- In scope：证据与质量上下文一致性、冻结 benchmark 一致性、历史 bar 冲突检查、baseline 证据资格、持仓页今日计划、冻结快照绑定、共享 runner 和第一次真实全持仓模拟。
- Non-goals：不新增数据库表；不回填旧 101 条记录；不自动分析全部持仓；不自动确认人工决定；不自动运行 outcome；不改变策略阶段；不产生订单。
- Risks：真实行情或 FX 可能不可用；首次 17 个持仓分析可能耗时较长；部分产品可能因条款、溢价、流动性或风险证据不足而只能显示资料不足。
- Done when：页面生成的 baseline 覆盖全部非零持仓；旧建议缺少不可改写 sidecar 时不能显示可复盘；详细分析始终绑定同一冻结快照；新建议只有证据和质量上下文一致时才显示已保存；真实首轮运行逐行终态且不修改持仓、现金、交易、风险政策或策略阶段。

## 用户流程

```text
生成今日计划
  -> 准备行情、benchmark 和 FX
  -> 冻结一个持仓快照
  -> 显示全部持仓的简单建议
  -> 用户选择需要详细分析的持仓
  -> 保存新建议和证据
  -> 用户接受、修改、否决或暂不行动
  -> 5/20/60 个交易日后显式评价
```

页面主状态只使用：

- `参考建议`：来自冻结快照中已有且证据完整的建议，本轮没有创建新样本。
- `新建议已保存`：本轮详细分析创建了新建议，证据 sidecar 和质量上下文均完整。
- `资料不足`：关键证据缺失、冲突或写入失败，不进入有效策略成绩。
- `等待确认`：新建议已保存，尚未记录人的决定。
- `等待结果`：人的决定已记录，但 5/20/60 个交易日尚未成熟。

内部 blocker、hash、枚举和英文状态不直接显示在日常主界面。

## 一致性规则

1. 证据完整与质量上下文完整必须一致。缺少 5/20/60 周期置信度时，证据不得标记为完整；不完整上下文不得计算完整 outcome。
2. benchmark 只能来自冻结研究快照和策略 manifest，调用方或模型输出不能覆盖它。
3. 行情准备核对抓取窗口内所有重叠日期；任一日期来源或 OHLC/成交字段冲突，只阻断对应标的，不覆盖已有行。
4. baseline 只有在 active signal 关联的不可改写 sidecar 存在、状态完整且引用匹配时，才允许显示为可参考建议。
5. 详细分析必须携带 baseline 的 `snapshot_hash` 和 `cutoff`。快照漂移返回重新生成今日计划，不静默采用新数据。
6. 未选择持仓不触发新闻、LLM 或新的决策样本。

## 数据与失败边界

允许写入：

- 行情和 FX 缓存；
- 新 DecisionSignal；
- 不可改写 evidence/quality sidecar；
- 人工反馈；
- 到期后的 outcome 行；
- 本地运行 manifest。

禁止修改：

- 持仓、现金、交易和公司行动；
- 标的核验结果和风险政策；
- Prompt、production strategy 和策略阶段；
- 旧决策证据；
- broker、订单或资金分配。

## 验证

- 后端 focused tests 覆盖证据/质量状态、benchmark 冻结、任意重叠 bar 冲突和 baseline sidecar 资格。
- Web tests 覆盖资料准备 -> 快照 -> baseline 顺序、17/17 覆盖、简单中文、失败状态和 bound analysis payload。
- 共享 runner tests 覆盖 prepare 先于 preflight、旧建议不冒充新样本、exact-trace evidence 校验和逐行失败隔离。
- Web lint、build、桌面与 390px 浏览器验收。
- 真实运行前后核对数据库备份、SHA-256、`quick_check` 和持仓/现金/交易/风险/策略阶段不变量；只允许预先声明的研究写入。
