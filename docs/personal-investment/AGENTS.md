# 个人投资学习主线协作规范

本文件只约束 `docs/personal-investment/`。它补充根目录 `AGENTS.md`；冲突时以根规则和用户当前明确要求为准。

## 1. 目标与边界

- 本目录是 DSA 个人 fork 的第二主线：用真实持仓问题驱动产品、财报、估值、组合和行为学习。
- 本目录不提供自动交易，不把 AI 输出、多模型一致或历史盈利当成独立证据，也不承诺任何收益率。
- DSA 账本是持仓、交易、现金、产品登记和正式风险政策的事实源；学习文档不得建立平行账本。
- 当前用户已明确授权在本公开仓库记录其持仓、成本、现金和资产规模。该授权不扩展到 API Key、登录凭证、券商账号、身份证明或其他人的信息。

## 2. 三份核心文件

- `个人投资学习档案.md`：慢变化基座，只维护目标、经验、认知缺口、证据规则和学习方法。
- `个人投资当前上下文.md`：快变化快照，通过 `data/stock_analysis.db` 只读刷新，必须保留生成时间和缓存价格时间。
- `个人投资学习记录.md`：追加式记录，只写经本人复核后真正改变理解或研究方式的结论，不回写旧判断。
- `投资学习启动Prompt.md`：开始新一轮学习时的执行模板，不是事实源，也不保存会话状态。

三份文件是仓库内唯一可迁移的学习记录。ChatGPT Project 或 Gemini 可作为远程主工作区，但远程聊天、远程记忆和自动摘要不是事实源。

## 3. 更新流程

1. 先读取三份核心文件，再确认当前问题属于画像更新、上下文刷新还是学习回写。
2. 涉及持仓事实时，只读查询 DSA；不得为了生成文档刷新行情、持久化 snapshot、写交易或改变风险政策。
3. 当前上下文必须区分账本事实、缓存估值、实时证据和推断；缓存价不能直接支持“现在是否买卖”。
4. 不临时强制跨币种换算，不把 DSA 未登记的资产、负债、应急资金或未来支出推定为零。
5. 所有动作讨论必须分开 `position_action` 与 `incremental_action`，并记录来源、反方、失效条件和复查点。
6. 远程 AI 会话结束后，只将本人审核过的“学习回写块”追加到学习记录，不同步完整聊天副本。

## 4. 默认学习顺序

1. 个人资金约束与投资政策。
2. 复杂产品身份和机制。
3. 组合重合与风险 X-ray。
4. 财报和现金流。
5. 估值与价格隐含预期。
6. 持续记录、基准比较和前向验证。

该顺序按永久损失风险和知识依赖排序，不是固定课程表。AI 证据核验、最强反方、失效条件和行为约束从第一步开始贯穿全程；只有真实持仓、资金期限或主要未知项变化时才调整顺序，并在学习记录说明理由。

## 5. 证据规则

- 公司、交易所、基金公司、指数公司和监管机构等一手来源优先。
- 财务数据、产品条款、ETF 成分与费率、监管规则、估值输入和市场事实按使用日期刷新。
- 视频、搜索摘要和 AI 只作为线索；影响 thesis、估值或动作的 claim 必须回到原始来源。
- 证据不足时明确写 `INSUFFICIENT_EVIDENCE` 或 `WAIT`，不得用流畅叙述填补空白。
- 长期年化 30% 是可调整愿望，40% 是压力情景；两者不得覆盖 DSA 正式风险政策或倒推出杠杆和仓位。

## 6. 最小验证

文档更新至少执行：

```bash
git diff --check -- AGENTS.md README.md docs/CHANGELOG.md docs/personal-investment
python3 scripts/check_ai_assets.py
```

刷新当前上下文时还要验证：

- 文档持仓代码集合与 DSA 非零持仓集合一致。
- 分账户现金和分币种汇总按服务端事件重放口径复核。
- 更新前后对 `portfolio_accounts`、`portfolio_cash_ledger`、`portfolio_corporate_actions`、`portfolio_instruments`、`portfolio_risk_policy`、`portfolio_trades` 做只读控制哈希对比。
- 若专用账本校验脚本不存在，可用 SQLite `.sha3sum --schema <table>`，但交付时必须说明所用方法。

纯文档改动不要求运行代码测试；若同时修改 DSA 运行逻辑，按根目录验证矩阵执行。

## 7. 发布与维护

- 每次发布只暂存本任务文件，不夹带工作区其他代码、配置或研究产物。
- 当前上下文一旦过期，先标记时间边界，再只读刷新；不得静默把旧缓存描述成实时行情。
- 根 README 只保留学习主线入口，详细方法和个人记录留在本目录。
- 只有真实坏案例、重复错误或事实源变化才扩充本规则，避免为了文档完整而增加形式主义。
